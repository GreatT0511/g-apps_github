SECTION 03

§3　ハンズオン① 教材の「最新版どれ?」をなくす

学年フォルダの「プリント_最終_改2_本当に最終.docx」問題を、リポジトリ1つで終わらせます。 置き場所は1つ、歴代の版は履歴に、変更の理由はコミットメッセージに。教科・分掌単位でそのまま使える型です。

校務での使いどころ: 学年・教科で共有するプリント、指導案、行事マニュアルの原本管理。

使う機能: リポジトリ＋アップロード＋履歴（History）＋共同編集者（Collaborators）

3-1

完成イメージ

  • リポジトリ sugaku-2nen（数学・中2教材）が非公開である
  • フォルダが単元ごとに分かれている（01_正負の数、02_文字式、…）
  • どのプリントも、Historyを見れば「いつ・誰が・なぜ変えたか」がわかる
  • 教科の同僚2人が共同編集者として入っている
3-2

手順1　箱を作ってファイルを入れる

  1. New repository → 名前は 教科-学年 の形（例: sugaku-2nen）→ Private → README付きで作成
  2. Add file → Upload files を開き、手元のプリント（Word・PDF・画像）をドラッグ&ドロップ
  3. コミットメッセージに「2学期分の既存プリントを一括登録」と書いて確定
  4. フォルダを作りたいときは、Add file → Create new file でファイル名の前に「01_正負の数/」のようにフォルダ名＋スラッシュを付けます
3-3

手順2　差し替えて、履歴を見る

  1. 差し替えたいファイルのあるフォルダで Upload files → 同じファイル名で上げ直す（自動で「新しい版」になります）
  2. コミットメッセージ: 「第3問を差し替え: 試験範囲の変更に合わせるため」
  3. ファイル一覧上部の History を開く——歴代の版と理由が一覧になり、どの版にも戻せます
description
WordとMarkdownの使い分け。Word・PDFも履歴管理はできますが、「どこが変わったか」の行単位比較はできません。これから新しく作る配布文書・手順書はMarkdown（.md）で書くと、変更箇所が色付きで見えるようになります。§2のテンプレの記法だけで十分です。
3-4

手順3　同僚を招待する

  1. リポジトリの Settings → Collaborators → Add people
  2. 同僚のユーザー名を入力して招待（相手にメールが届き、承認すると編集できるようになります）
  3. 招待した人にも§2の「コミットメッセージの型」を共有しておく——ここを揃えるのが運用のコツです
gpp_maybe
置いてはいけないもの。Privateでも、成績・名簿・住所・顔写真など個人情報はリポジトリに置かない。GitHubは教材と手順書の箱、個人情報は校務支援システムの中——この線引きを最初に学年で合意してください。

ワーク — 自分の「最新版どれ?」を1つ持ち込む

いま手元で版が散らかっているファイルを1つ選び、リポジトリを作って登録→1回差し替え→Historyで確認、まで回してください（10分）。終わったら隣の人とHistoryを見せ合い、コミットメッセージが「未来の自分に通じるか」を確かめます。
