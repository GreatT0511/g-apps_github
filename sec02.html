SECTION 02

§2　GitHubの基礎 — 4つの言葉と、最初のリポジトリ

覚える言葉は4つだけ。そしてこの講座ではプログラミングもコマンドも使いません—— すべてブラウザの画面操作だけで完結します。10分で最初のリポジトリを作り、最初の履歴を残します。

ここまで: §0〜§1で、安全なアカウントができました。この章: 最初の箱（リポジトリ）を1つ作り、「編集→保存」を3周して体で覚えます。次: §3で、この箱をそのまま使ってプリントの版管理を体験します。

2-1

4つの言葉を、学校の言葉に訳す

folder

リポジトリ

=書類箱。1つのテーマ（教科・学年・探究1人分）につき1箱。中にフォルダとファイルを入れます。公開（Public）か非公開（Private）かを箱ごとに選べます。

save

コミット

=理由つきのセーブ。変更を保存するとき、必ず「なぜ変えたか」を一言書きます。この一言の積み重ねが、あとで宝になります。

sticky_note_2

イシュー（Issue）

=箱に貼る付箋。「ここ直したい」「これどうする?」という相談カード。解決したら閉じます。閉じた付箋も全部残ります。

call_merge

プルリクエスト

=「こう直したら?」の提案書。相手のファイルを直接書き換えず、変更案として送り、相手が採用・却下を決めます。§6の主役です。

history_edu
コミットメッセージは「未来への手紙」。「何を: なぜ」の一言を毎回残すだけで、来年の自分と、引き継ぐ相手が助かります。ここがこの道具を学校で使う一番の理由です。
2-2

最初のリポジトリを作る

  1. 右上の ＋ → New repository
  2. Repository name に hello-github と入力（全員この名前で。半角でそのまま打ちます）
  3. Private（非公開）を選ぶ——迷ったら常にPrivateから
  4. Add a README file にチェックを入れて Create repository
2-3

編集→コミットを3周して、体で覚える

操作は毎回同じ「鉛筆マーク → 直す → Commit changes...」の1往復です。お題は決まっています。3周してください。

周1　テンプレを貼る

  1. README.md の右上の鉛筆マークを押して編集画面へ
  2. 下のテンプレを貼り付けて、書き換えるのは2か所だけ：「（ユーザー名）」を自分のユーザー名に、「はじめた日」を今日の日付にする
  3. Commit changes... → メッセージ: 「READMEを書き換え: 自分の練習箱だと分かるようにするため」（何を・なぜの型です）

周2　1行足す

  1. もう一度鉛筆マーク。「## メモ」の下に 「- 今日おぼえた言葉: リポジトリ＝箱」 の1行を追加
  2. Commit changes... → メッセージ: 「おぼえた言葉を追加: 忘れないうちに残すため」

周3　もう1行足す

  1. もう一度鉛筆マーク。「- 管理者: …」の下に 「- 担当教科: ○○」（自分の教科）を追加
  2. Commit changes... → メッセージ: 「担当教科を追加: 誰の箱か分かるようにするため」
  3. ファイル一覧上部の History（時計マーク）を開く——3件の履歴が理由つきで並んでいれば合格です
READMEのテンプレ（貼り付けて書き換え） クリックでコピー
# このリポジトリについて - 何の箱か: GitHub練習用 - 管理者: （ユーザー名） - はじめた日: 2026-08-19 ## メモ Markdownは「# が見出し」「- が箇条書き」だけ覚えれば始められます。
2-4

コミットメッセージの型（これだけ配れば回る）

コミットメッセージの型 クリックでコピー
（何をした）: （なぜそうした） 例: 第3問を差し替え: 試験範囲の変更に合わせるため AI案を修正して採用: 用語が教科書と違ったため言い換えた グラフを削除: 出典が確認できなかったため
code
発展: リポジトリを開いた状態でキーボードの .（ピリオド）を押すと、ブラウザ内に本格エディタ（github.dev）が開きます。複数ファイルをまとめて編集したくなったら思い出してください。今日は使いません。
2-5

GitHub Copilot — GitHubの中の生成ＡＩを、無料枠で試す

GitHub Copilotは、GitHubに組み込まれた生成ＡＩアシスタントです。プログラマーのコード補完機能として有名ですが、ブラウザ版はふつうのチャットとして使えて、自分のリポジトリの中身について質問できるのが特長です。ホーム画面の「Ask anything」欄や、画面上部のCopilotアイコンが入口です。

  • 無料でできること（Copilot Free）: 個人アカウントなら申込みだけで、チャット月50回・コード補完月2,000回まで無料。クレジットカード登録は不要です。§0の作成時に「GitHub Copilot」へチェックを入れた人はそのまま使えます（入れていなくても、Copilotアイコンから後で有効化できます）
  • 先生の使いどころ: 自分のリポジトリのREADME要約・ファイルの説明、Markdownの書き方の相談、配布文書の下書き。「GitHubの操作が分からないときに、その画面で聞ける」のが一番の実用です
  • 約束ごと: 生成物は必ず自分で確かめてから使う（コミットメッセージに「Copilot案を修正して採用」と書けるのが§2-4の型です）。個人情報・成績は入力しない。生徒アカウントでの利用ルールは§7で扱います

ワーク — Copilotに2つだけ聞く（5分）

  1. ホームの「Ask anything」欄（または上部のCopilotアイコン）を開き、「私の hello-github リポジトリのREADMEを、3行で要約してください」と送る——出てきた要約が本当に合っているか、自分のREADMEと見比べて確かめる
  2. 続けて 「Markdownで、月曜から金曜までの時間割表のひな形を作ってください」と送る——出てきた表をコピーし、READMEの「## メモ」の下に貼り付けて、メッセージ 「Copilotの表ひな形を追加: Markdownの表を試すため」でコミット

チェックポイント: 貼る前に、読んで確かめましたか? 生成ＡＩの出力を「確かめてから採用し、履歴に理由を残す」——この1往復が、生徒に見せたい使い方そのものです。

ここまでのチェック

  • hello-github リポジトリがある
  • コミットが2つ以上あり、Historyで「何を: なぜ」が読める
  • 4つの言葉を隣の人に自分の言葉で説明できる（リポジトリ=箱、コミット=理由つきセーブ、Issue=付箋、プルリク=提案書）
  • Copilotの回答を「確かめてから」採用した（うのみにしなかった）
