SECTION 03

§3　ハンズオン① 教材の「最新版どれ?」をなくす

学年フォルダの「プリント_最終_改2_本当に最終.docx」問題を、リポジトリ1つで終わらせます。 このワークは§2で作った hello-github の続きでそのまま行います。新しい準備は不要、教材はこのページからコピペするだけです（10分）。

今日体験すること: プリントを1枚入れる → 配布後の訂正を2回する → 履歴と差分で「最新版が常に1つ」を確かめる。

使う機能: Create new file＋編集（鉛筆マーク）＋履歴（History）＋差分表示

3-1

完成イメージ

  • hello-github の中に「夏休みの課題」プリントが1つだけある（_最終_改2 のようなコピーはない）
  • Historyを見ると「初版 → 訂正① → 訂正②」が理由つきで並んでいる
  • 訂正のコミットを開くと、変わった行だけが赤と緑で表示される
3-2

手順1　プリントを1枚入れる（3分）

  1. hello-github を開き、Add file → Create new file
  2. ファイル名: プリント_夏休みの課題.md
  3. 下のプリント原稿をそのまま貼り付ける（書き換え不要）
  4. Commit changes... → メッセージ: 「夏休み課題プリントを登録: 配布用の初版」
プリント原稿（そのまま貼り付け） クリックでコピー
# 夏休みの課題について 配布日: 7月18日 ／ 対象: 2年○組 ## 提出するもの - ワークブック p.10〜p.35 - 自由研究レポート（1枚以上） ## 提出日 9月1日 に教室で回収します。 ## 注意 - 名前を書いたか確認しましょう - なくした人は担任まで
3-3

手順2　配布後の訂正①（3分）

配布した後で、始業式の日程が変わったとします。ファイルを開いて鉛筆マークで編集し、提出日の行を1か所だけ直します。

  1. 「9月1日」を「9月2日」に書き換える
  2. Commit changes... → メッセージ: 「提出日を9月2日に訂正: 始業式の日程変更のため」
  3. ファイル一覧上部の History を開く——初版と訂正①が理由つきで並んでいます
3-4

手順3　訂正②と、差分の見方（4分）

今度は国語科から「読書感想文も回収してほしい」と依頼が来たとします。

  1. 「提出するもの」に 「- 読書感想文（1冊分）」 の1行を追加
  2. Commit changes... → メッセージ: 「読書感想文を追加: 国語科からの回収依頼のため」
  3. History を開き、いまのコミットをクリック——追加した行が緑、消した行が赤で表示されます
difference
これが「最新版どれ?」の答えです。ファイルは常に1つ、過去の版は履歴に、変更の理由はメッセージに、変わった場所は色に。「_最終_改2」を作る理由が、もうどこにもありません。

ワーク — ペアでHistoryを見せ合う（5分）

隣の人とお互いのHistoryを開き、コミットメッセージが「未来の自分（来年この訂正の理由を忘れた自分）に通じるか」を確かめてください。早く終わったペアは、手元にある実物のプリントで同じ流れ（登録→1回訂正→History）をもう1周どうぞ。

3-5

教室に持ち帰るときの型（あとで読めばOK）

  • 箱の作り方: 教科・分掌ごとに 教科-学年（例: sugaku-2nen）の名前で Private リポジトリを1つ。フォルダは Add file → Create new file でファイル名の前に「01_正負の数/」のようにフォルダ名＋スラッシュ
  • Word・PDFも入る: Add file → Upload files にドラッグ&ドロップ。同じファイル名で上げ直せば自動で「新しい版」になります。ただし行単位の色付き差分はMarkdownだけの特典——新しく作る配布文書はMarkdownで
  • 同僚を入れる: Settings → Collaborators → Add people で招待し、§2の「コミットメッセージの型」を一緒に配る——ここを揃えるのが運用のコツです
gpp_maybe
置いてはいけないもの。Privateでも、成績・名簿・住所・顔写真など個人情報はリポジトリに置かない。GitHubは教材と手順書の箱、個人情報は校務支援システムの中——この線引きを最初に学年で合意してください。
