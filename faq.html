Q&A

よくある質問 — 事前にどうぞ、当日もどうぞ

研修の前後に届く質問をまとめました。ここにない疑問は、当日その場で聞いてください。「初歩的すぎるかな」という質問ほど、会場の10人が同じことを思っています。

A

アカウントとお金のこと

この講座の内容はすべて無料の範囲です。無料プランで非公開リポジトリは作り放題、共同編集者も無制限、Webページ公開(§4)も無料です。有料が関係するのは「非公開リポジトリのままWeb公開したい」場合など、ごく一部だけ。まず無料で始めて困ることはありません。

だめではありません。学校で禁止されていなければ、学校のアカウントで作るのももちろん推奨です。ただし転勤などでアドレスが変わるときは、先にGitHub側のメールアドレスを変更する必要があります。本日の研修では、学校ごとのデータ利用規則の確認を挟まずに進めるため、個人のGoogleアカウントで作成してください(§0・§1-1)。

変えられます。ただしユーザー名はURLの一部なので、変えると配布済みのリンクが切れます。最初に「半角英数とハイフン・本名フルネームや学校名は入れない」で決め切るのがおすすめです(§1-1)。

Google連携で作った場合(§0のルート)は、GitHub独自のパスワードを覚える必要がそもそもありません。Googleにログインできれば入れます。メール+パスワード方式で作った場合は、ログイン画面の「Forgot password?」からメールで再設定できます。

何も起きません。アカウントもリポジトリも個人の資産として、そのまま持ち歩けます。これがこの道具の大きな価値です。学校メールで作っていた場合だけ、アドレスが失効する前に Settings → Emails で個人メールに変更してください。

規約上、無料の個人アカウントは1人1つが原則です。用途を分けたい場合は、アカウントを増やすのではなく、学校・教科用の「Organization(組織)」を無料で作って、個人アカウントで参加する形にします。運用が本格化してきたら検討しましょう。

B

安全とルールのこと

招待した共同編集者以外には、検索にも出ず、URLを知っていても見えません。ただし「見えないから置いていい」ではなく、成績・名簿・住所・顔写真などの個人情報はPrivateでも置かないのがこの講座のルールです(§3)。個人情報は校務支援システムの中、GitHubは教材と手順書の箱です。

生徒の作品の著作権は生徒本人にあります。置く前に本人(と保護者)の同意を取り、まずPrivateで始めるのが原則です。公開する場合は氏名の扱い・公開範囲を含めて§7の配布ひな形で合意してから。「勝手に世界公開」が一番のトラブルの元です。

GitHubの規約で13歳以上です。中学1年生は誕生日前の生徒がいる点に注意してください。小学校では生徒にアカウントを作らせず、先生の画面を映して見せる・先生のリポジトリに作品を預かる形で使います(§7)。

自治体のフィルタリングでブロックされている場合は、情報担当を通じて解除申請をします。申請時の説明は「開発者向けサイト」ではなく「版管理機能つきの教材共有・公開サービス。文書の履歴が残る共有フォルダとして使う」と用途で伝えるのがコツです。github.com と github.io (公開ページ)の2ドメインを申請してください。

3点セットで通ります。①用途:「教材・手順書の原本管理(履歴つき共有フォルダ)」 ②線引き:「個人情報は置かない。校務支援システムと役割分担」 ③根拠:「無料・国内外の教育機関で利用実績」。§7の配布ひな形がそのまま説明文書になります。

C

操作のこと

大丈夫です。今日のワークも「プリント_夏休みの課題.md」と日本語で進めます。例外は§4でWeb公開するページのファイル——URLの一部になるので、半角英数(index.htmlなど)にしておくと共有しやすくなります。

使えます。ドラッグ&ドロップで置けて、同名で上げ直せば版も重なります。ただし「どの行が変わったか」の色付き比較はMarkdownだけの特典です。今あるWord資産はそのまま入れる、新しく作る配布文書はMarkdownで——この使い分けで十分です(§3)。

ブラウザからすべての操作ができ、公式アプリもあります。閲覧・確認・小さな修正はスマホで十分ですが、今日のような編集ワークはキーボードのあるPC・Chromebookが楽です。

ファイルの削除はただのコミットなので、Historyからいつでも戻せます(§3の手順4と同じ要領)。リポジトリごと削除した場合も、90日以内なら Settings → Deleted repositories から復元できます。「取り返しがつかない操作」はほぼありません。

そのままで大丈夫です。ブラウザ操作では過去のメッセージは直せませんが、履歴の価値は完璧さではなく回数です。気になるなら次のコミットのメッセージで「(先ほどの訂正: ○○の誤りでした)」と補足すれば十分です。

ブラウザからのアップロードは1ファイル25MBまで、リポジトリ全体は1GB以内が目安です。プリント・指導案・写真なら余裕ですが、授業動画などの大きなファイルは不向きです。動画はDriveやYouTube(限定公開)に置き、GitHubにはリンクを書くのが定石です。

今日使うのは「# が見出し」「- が箇条書き」の2つだけです。それ以上は必要になったときに調べれば足ります。§2のテンプレとこのサイトの原稿をコピペして直すところから始めれば、書き方は自然に手に入ります。

D

運用と使い分けのこと

両方使います。Driveの強みは同時編集と気軽な共有、GitHubの強みは「版・理由・差分が残る原本」です。使い分けの目安: 作りかけの共同作業はDrive、確定版・配布物・積み上げたい記録はGitHub。「_最終_改2」が生まれがちな文書ほどGitHub向きです。

役割が違うので併用です。課題の配布・回収・締切管理はClassroomのまま。GitHubは「提出して終わり」にしたくない作品・探究・教材の積み上がる置き場です(§5)。Classroomのお知らせに、生徒のリポジトリや公開ページのリンクを貼る形でつながります。

説得より実物です。まず自分の教科の箱(§3)を1つ作って運用し、「最新版どれ?」と聞かれたときにリンク1本で返す——それが一番の営業になります。共同編集者への招待は、相手が便利さを見てからで遅くありません。

いつでも全部持ち出せます。各リポジトリは Code → Download ZIP で丸ごとダウンロードでき、ファイルはただのWord・PDF・テキストのまま。特殊な形式への囲い込みがないので、「やめるコスト」がほぼゼロです。安心して始めてください。
